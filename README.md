## API
**Название:** Nager.Date Public Holiday API  
**Описание:** Бесплатный API для получения информации о государственных праздниках более чем 100 стран. API предоставляет данные о праздниках, включая даты, локальные и английские названия, типы праздников (государственные, банковские, школьные и т.д.), региональную информацию.

**Базовый URL:** `https://date.nager.at/api/v3/`

**Основные endpoints:**
- `GET /AvailableCountries` - список всех доступных стран
- `GET /PublicHolidays/{year}/{countryCode}` - список праздников для указанной страны и года

**Особенности:**
- Не требует API ключа
- Нет ограничений по количеству запросов (rate limit)
- Всегда актуальные данные

## Room 
### Что есть
3 FavoriteEntity 
1) FavoriteHoliday - Основная таблица с информацией о празднике.
   - id (String, primary key) – уникальный идентификатор праздника (скорее всего, приходит с сервера).
   - date – дата праздника.
   - localName – название на местном языке.
   - name – общее название (например, на английском).
   - countryCode – код страны.
   - global – флаг, является ли праздник глобальным.

2) Types - Хранит типы праздника (например, «Public», «Bank»).
   - id (autogenerated) – первичный ключ.
   - holidayId – внешний ключ, ссылается на favourite_holiday(Id). При удалении праздника все связанные типы удаляются каскадно.
   - name – название типа.

3) Conties - Содержит графства (регионы), в которых праздник действует.
   - id (autogenerated) – первичный ключ.
   - holidayId – внешний ключ к favourite_holiday(Id) с каскадным удалением.
   - name – название региона.

Связи: один праздник может иметь много записей в favourite_types и favourite_counties (one-to-many). В DAO определены методы для вставки (с конфликтной стратегией REPLACE), удаления по идентификатору и получения всех избранных праздников вместе с их типами и графствами через транзакционный запрос.
Сама БД денормализована (записи типов/регионов дублируются), так как было бы необходимо создавать отдельные таблицы со связками many-to-many и заранее узнавать какие есть данные "всевозможные", а на это нет особых причин вроде

### Сценарий
Приложение получает данные о праздниках из внешнего API. Пользователь может добавлять праздники в избранное. При этом выполняется транзакция:

- в favourite_holiday сохраняется основная информация о празднике;

- в favourite_types и favourite_conties построчно записываются все соответствующие типы и графства (каждая строка связывается с holidayId).

- При просмотре списка избранного вызывается метод getAll(), который объединяет данные из трёх таблиц и возвращает объекты FavoriteHolidayWithAll, содержащие праздник и два списка (типов и графств). Затем эти данные преобразуются в доменную модель Holiday для отображения в UI.

- Если пользователь удаляет праздник из избранного (deleteById), благодаря внешним ключам с CASCADE автоматически удаляются и все связанные типы и графства.

## Как проверить?
1) Выберите страну,год из списка
2) Отметьте в избранное (нажмите на сердечко)
3) Зайдите в избранное и проверьте что выбрали
4) Выйдите из приложения
5) Запустите заново и проверьте избранное
