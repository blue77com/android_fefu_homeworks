**Приложение:** «Мой Календарь» — персональный календарь заметок с праздниками

## Что добавлено в финальной работе

### Новые экраны
- **Настройки** — тема оформления и выбор страны для праздников
- **История заметок** — список всех пользовательских заметок с переходом к дате в календаре
- **Экран заметки** — создание и редактирование событий/заметок
- Категории заметок (личное, работа, праздники, дедлайн)
- Поддержка повторяющихся заметок (неделя / месяц / год)
- Чеклист внутри заметки с отметкой прямо из списка дня

### Расширение существующих экранов
- Теперь API объеденяет Календарь с заметками в пользу второго 
- Фильтр «только избранные заметки»

### Архитектура и данные
- **DataStore** для настроек (тема, страна)
- **Room** для заметок, кэша праздников и стран
- **WorkManager** — ежедневные уведомления и фоновое обновление кэша

## Новые пользовательские данные

### DataStore (настройки и предпочтения)
`selected_country_code` — Код страны для загрузки праздников 
`app_theme` — Тема: светлая / тёмная / системная 

### Room (пользовательские данные и кэш)

| Таблица | Назначение |
|---------|------------|
| `notes` | Личные заметки и события (избранное — поле `isFavourite`) |
| `holiday_cache` | Кэш праздников по стране и году |
| `countries` | Кэш списка стран |

### Модель заметки (`Note`)
- `text`, `description` — заголовок и описание
- `date` — дата события
- `isFavourite` — избранная заметка
- `category` — категория (личное, работа, праздники, дедлайн)
- `repeatMode` — режим повтора (нет / неделя / месяц / год)
- `checklist` — список пунктов с флагом выполнения

Пользовательские данные создаются и изменяются через UI, хранятся локально и влияют на отображение календаря и уведомлений.

## Новые пользовательские сценарии

### 1. Личные заметки и события (существенный)
**Цепочка:** `NoteDetailScreen` → `HolidayViewModel` → `HolidayRepository` → `NoteDao` → Room

Пользователь может:
- создать заметку на выбранный день;
- задать категорию, описание, режим повтора и чеклист;
- отметить заметку избранной;
- видеть повторяющиеся заметки на соответствующих датах в календаре;
- отмечать пункты чеклиста из списка дня;
- удалить заметку.

**Результат:** персональный слой поверх праздников API — календарь отражает и внешние, и пользовательские события.

### 2. Offline-first загрузка праздников (существенный)
**Цепочка:** `HolidayListScreen` → `HolidayViewModel` → `HolidayRepository` → `HolidayCacheDao` / `NagerApi`

Поведение:
1. UI подписан на `observePublicHolidays()` — сразу показывает данные из Room.
2. В фоне вызывается `refreshPublicHolidays()` — обновление из сети.
3. При успехе кэш перезаписывается, UI обновляется реактивно.
4. Без сети приложение работает с кэшем; заметки доступны всегда.
5. Если кэша нет и сеть недоступна — показывается ошибка и кнопка «Повторить».

Аналогично для списка стран: `observeCountries()` + `refreshCountries()`.

### 3. Настройки приложения
**Цепочка:** `SettingsScreen` → `SettingsViewModel` → `SettingsRepository` (DataStore) / `HolidayRepository`

Пользователь выбирает тему и страну. Изменения сохраняются и восстанавливаются после перезапуска. Смена страны автоматически перезагружает праздники для выбранного года.

### 4. История заметок
**Цепочка:** `NotesHistoryScreen` → `HolidayViewModel` → Room (заметки)

Экран показывает все заметки пользователя. По нажатию открывается соответствующая дата в календаре. Работает без сети.

### 5. Ежедневные уведомления (фоновый сценарий)
**Цепочка:** `DailyWorker` → `HolidayRepository` + `SettingsRepository` → `NotificationHelper`

Раз в сутки worker:
- собирает заметки на сегодня (избранные помечаются отдельно);
- обновляет кэш праздников (если есть сеть);
- читает праздники из кэша;
- отправляет сводное уведомление.

## Offline-first: как устроено

```
┌─────────────┐     observe (Flow)      ┌──────────────┐
│     UI      │ ◄────────────────────── │  Room (кэш)  │
│  ViewModel  │                         │  + заметки   │
└──────┬──────┘                         └──────▲───────┘
       │ refresh (suspend)                       │
       ▼                                         │ insert
┌─────────────┐     HTTP                  ┌──────┴───────┐
│ Repository  │ ──────────────────────► │  Nager API   │
└─────────────┘                         └──────────────┘
```

**Принципы:**
- Локальное хранилище — первичный источник для UI (Flow из Room).
- Сеть используется для обновления и синхронизации, а не как единственный источник состояния экрана.
- Заметки и кэш доступны без интернета.
- При ошибке сети без кэша пользователь видит сообщение и может повторить загрузку.

**DataStore** хранит только настройки. **Room** — заметки, кэш праздников и стран.

## Фоновая обработка (WorkManager)

| Компонент | Назначение |
|-----------|------------|
| `HolidayApplication` | Инициализация WorkManager через Hilt, планирование задачи |
| `DailyWorker` | Ежедневная фоновая работа (период 1 день) |

**`DailyWorker` выполняет:**
1. Чтение заметок на сегодня из Room (избранные — с префиксом «⭐»).
2. Попытку обновить кэш праздников для выбранной страны.
3. Чтение праздников из кэша (offline-safe).
4. Показ push-уведомления со сводкой событий.

Worker использует `SettingsRepository` для получения активной страны и `HolidayRepository` для данных — это часть общей offline-first логики, а не изолированная заглушка.

## Сборка и запуск

1. Открыть проект в Android Studio.
2. Синхронизировать Gradle.
3. Запустить на устройстве/эмуляторе с **API 35+** (`minSdk = 35`).
4. При первом запуске выбрать страну в **Настройках** — после этого загрузятся праздники.
